- Kiosk punch photos go through the punch-photo edge function only (private bucket, no browser storage policies) because most users sign in with app sessions, not Supabase Auth.
- Phone alerts use Firebase via the connector gateway (supabase/functions/_shared/fcm.ts); device addresses live in server-only fcm_tokens, registered through the notifications function, and the browser worker is public/firebase-messaging-sw.js in its own scope so it never clashes with the main offline sw.js.
- Firebase web-push browser values are public and live in src/config/firebaseWeb.ts (connector VITE_ vars are optional overrides) because the connector never synced them into the build and the Vercel build has no connector env.
- Timed alerts run from the existing 15-minute database timer calling the notifications function (run_scheduler); timing rules live in supabase/functions/_shared/alertSlots.ts (pure, unit-tested) and alert_runs claims each slot first so a slot is never sent twice.
- data-api writes are reduced to the fixed per-table lists in supabase/functions/data-api/writableFields.ts (narrower lists for staff); when a migration adds a column the app must write, add it there or it is silently dropped.
- Edge functions map a Supabase Auth user to app_users only via findAppUserForAuth in _shared/caller.ts (auth_id first; email fallback only for confirmed emails on unlinked profiles) so nobody inherits another account by email.
- send-notification accepts only fixed templates with validated params (no caller-written title/body), and notify-payslip builds the email link itself from a verified payslip_links token and an allowed app origin (APP_ORIGINS secret adds more), to stop managers sending arbitrary text or links.
- Staff password recovery is request → in-person manager approval with a 6-digit code → completion from the same phone holding a secret request token (staff-password-reset); manager-issued PINs are no longer accepted.
- Install and permission prompts live only in src/components/InstallAndPermissions.tsx (mounted once in main.tsx); timing rules are pure in src/utils/installPromptTiming.ts so back-off stays unit-tested.

- Shared fingerprint attendance accepts only external FIDO2 reader/security-key credentials, enrolled and verified (signature + counter) by the fingerprint-auth function, because a phone's own unlock cannot tell staff apart; data-api cannot create fingerprint rows.
- Fingerprint punches are decided and written only by fingerprint-auth (auth_verify) after signature verification, using the shared rules in supabase/functions/_shared/fingerprintPunch.ts, so the browser can never choose the staff member, time or IN/OUT.
